Nenhuma IA é chamada ainda. A task define como a Juniper vai conversar com qualquer modelo: o formato das mensagens, os erros possíveis e o contrato que cada provider assina.

2. As palavras: os tipos

Arquivo types.py. Todos são imutáveis: depois de criados, não mudam.

Message

Uma "carta" da conversa.
  • role: system, user, assistant ou tool
  • content: o texto (pode ser vazio)
  • tool_calls: pedidos de ferramenta
  • tool_call_id: a qual pedido responde

ToolCall

O modelo pedindo uma ferramenta.
  • id: identifica o pedido
  • name: ex. open_app
  • arguments: dict já pronto, não texto JSON

LLMResponse

A resposta completa.
  • message: a Message do assistente
  • model e provider
  • usage: TokenUsage (opcional)
  • finish_reason

StreamChunk

Um pedaço da resposta, no modo streaming.
  • delta: o texto novo
  • tool_calls: só no fim, completos
  • usage e finish_reason: só no último

TokenUsage

O consumo. Todos os campos são opcionais, porque nem todo provider informa.
  • prompt_tokens
  • completion_tokens
  • total_tokens

3. As palavras em ação

Exemplo: "abre o Firefox pra mim". Cada balão é uma Message.

system
Você é a Juniper, sarcástica e técnica…Message(role="system", content="…")
user
Abre o Firefox pra mimMessage(role="user", content="Abre o Firefox pra mim")
assistant
(sem texto) pede uma ferramentaMessage(role="assistant", content=None, tool_calls=(ToolCall(id="c1", name="open_app", arguments={"target": "firefox"}),))
tool
A ferramenta devolve o resultadoMessage(role="tool", content="ok", tool_call_id="c1", name="open_app")
assistant
"Pronto, Firefox aberto. De nada."Message(role="assistant", content="Pronto, Firefox aberto. De nada.")

O tool_call_id="c1" liga a resposta da ferramenta ao pedido. Esse ciclo se repete até o modelo responder só com texto.

5. O contrato: o que todo provider precisa saber fazer

Arquivo base.py. Um provider que não implementa os três métodos nem consegue ser criado.

chat()

Manda as mensagens e espera a resposta inteira.
await provider.chat(msgs, tools=…)
→ LLMResponse

stream()

Manda as mensagens e recebe a resposta aos pedaços, para mostrar na tela enquanto chega.
async for c in provider.stream(msgs):
    print(c.delta)

health_check()

Pergunta "você está vivo?". Útil para o router e para diagnóstico.
await provider.health_check()
→ True | False
Como o streaming chega
"Pr""onto"", Fire""fox aberto." "" + finish_reason="stop" + usage

Juntando todos os delta você obtém o mesmo texto que o chat() devolveria. O último pedaço traz o motivo do fim e o consumo.

6. Quem usa o quê

T-012 / T-013 implementam o contrato e traduzem entre o formato do modelo e as Message/ToolCall, e entre os erros do modelo e os LLM*Error.

T-015 (router) usa os tipos de erro para trocar de provider.

T-030 (agente) usa só Message, ToolCall e o contrato, sem saber qual modelo está por trás.
