# ADR-003 — Configuração

- **Status:** Aprovado

- **Autor:** Petrus Rennan + Lead Architect (Juniper)
- **Contexto do Sprint:** Sprint 1 — "Hello Agent"
- **Relaciona-se com:** T-003, T-010

---

## Contexto

O Juniper v3 precisa de configuração para:

- Ordem de prioridade dos providers de LLM (Groq, Ollama)
- Modelos default de cada provider
- Timeouts
- Idioma e iterações máximas do agente
- Política de segurança das tools (allowlist de shell)
- Credenciais sensíveis (chaves de API)

Credenciais **não podem** ser versionadas. Preferências **devem** ser versionadas (auditáveis, revisáveis em PR). Precisamos separar essas duas classes.

---

## Decisão

Adotamos uma abordagem híbrida com **três camadas de precedência**:

1. **Variáveis de ambiente** (maior precedência) — segredos e overrides pontuais
2. **`config.yaml`** (versionado) — preferências do projeto
3. **Defaults no código** (menor precedência) — valores sensatos

### Arquivos

- **`config.yaml`** — versionado, com `config.yaml.example` como template. Contém preferências. Nunca contém segredos.
- **`.env`** — **NUNCA** versionado (bloqueado em `.gitignore`), com `.env.example` como template. Contém segredos e overrides locais.

### `config.yaml.example` (draft inicial)

```yaml
llm:
  priority: [groq, ollama]
  groq:
    model: llama-3.3-70b-versatile
    timeout: 30
  ollama:
    url: http://localhost:11434
    model: llama3.1
    timeout: 120

agent:
  max_iterations: 5
  language: pt-BR

tools:
  security:
    shell_allowlist: [git, ls, cat, grep, rg, fd, jq, find, wc, head, tail]
    shell_require_confirmation: true
    confirmation_timeout: 60
```

### `.env.example` (draft inicial)

```bash
# Providers
GROQ_API_KEY=

# Overrides opcionais (se ausentes, config.yaml manda)
# OLLAMA_URL=http://localhost:11434
# JUNIPER_LOG_LEVEL=INFO
```

### Carregamento

- **Biblioteca:** `pydantic-settings`.
- Modelo de settings tipado em `brain/config.py`.
- Precedência ENV > YAML > defaults é nativa do `pydantic-settings` quando configurado com `yaml_file` + `env_file`.
- **Falha cedo:** se `config.yaml` não existir e não houver `config.yaml.example`, o boot aborta com erro claro.

### Logs

- Diretório de logs runtime: `~/.juniper/logs/` (fora do repo).
- Formato: JSON Lines (`.jsonl`), um evento por linha.
- Log estruturado inclui: timestamp, tool, tier, decisão, output, exit code.

---

## Consequências

### Positivas

- Trocar modelo Groq ou prioridade de providers não exige editar código.
- Segredos fora do repo por design.
- CI pode rodar com `config.yaml.example` + env fake.
- Configuração auditável via PR.

### Negativas

- Duas fontes de verdade (YAML + ENV) exigem documentação clara da precedência. **Mitigação:** `.env.example` com comentários indicando quando cada variável se aplica.
- `pydantic-settings` adiciona uma dependência. Aceitável — é padrão de facto e traz validação de tipos de graça.

---

## Alternativas consideradas

1. **Só `.env`.** Rejeitada: listas complexas (como allowlist de shell) ficam horríveis como strings separadas por vírgula. YAML é mais expressivo.
2. **Só `config.yaml` (segredos em campos).** Rejeitada: risco de commitar segredos por acidente.
3. **TOML.** Rejeitada: YAML é mais legível para estruturas aninhadas e já é familiar para o usuário.
4. **Configuração em código Python.** Rejeitada: viola separação código/config, exige rebuild para trocar valor.
