T-060 — Aceite do marco da Sprint 2

O marco: a Juniper lembra que você prefere ZSH, que odeia tabulação com espaço e que o projeto X usa Laravel 11, entre sessões, e deixa de ser estranha. Aqui estão o teste automatizado que comprova o fluxo e o roteiro para você validar com o LLM, o modelo e o banco reais. Arquivo do teste: tests/test_acceptance_sprint2.py.

1. O teste automatizado (roda no CI)

Ele abre o chat de verdade (cli._chat) várias vezes, como várias sessões na mesma máquina e no mesmo banco:

SessãoO que acontece
1Você diz "Prefiro ZSH", "Odeio tabulação com espaço" e "O projeto X usa Laravel 11" e fecha o terminal. A Juniper avisa "Guardei 3 coisas sobre você".
2 (nova)"Qual shell eu uso?" → ZSH. "Como devo indentar?" → tabulação. "Que framework PHP o projeto X usa?" → Laravel 11 (associação por significado). Só a memória relevante entra no prompt de cada pergunta.
3"Migrei o X para o Laravel 12": a memória nova substitui a antiga, que fica superseded e deixa de ser ativa. A pergunta seguinte responde Laravel 12.
4"Esquece o projeto X": a Juniper pergunta antes e nada some; depois do "sim", o projeto X some do banco (inclusive a versão antiga) e não é mais recuperado. ZSH e tabulação continuam.

O que é real: chat, agente, sessão, extração, deduplicação e atualização, filtro de segredos, VectorStore, recuperação, injeção no prompt, tools e confirmação.

O que é simulado: o LLM (regras fixas que só sabem o que está no bloco <memorias> que chegou ao prompt), o modelo de embeddings (um mapa de conceitos que faz "PHP" e "Laravel" caírem juntos) e o MongoDB (collection em memória). O teste prova que o encanamento funciona; não prova a qualidade do LLM nem do modelo reais. Para isso, use o roteiro abaixo.

2. Roteiro manual, com tudo real

Pré-requisitos: Docker rodando, juniper install --memory=mongo feito (ou memory.session.store: mongo e o banco no ar), chaves de LLM no .env. Na primeira conversa com memórias guardadas, a Juniper baixa o modelo de embeddings (~120 MB).

# 0. comece limpo (opcional)
juniper memory list

# 1. sessão 1: diga e feche com /sair (a extração roda na saída)
juniper
  > prefiro ZSH
  > odeio tabulação com espaço
  > o projeto X usa Laravel 11
  > /sair                      # deve dizer "Guardei N coisas sobre você"
juniper memory list            # confira o que foi guardado (e o que NÃO foi)

# 2. sessão 2 (nova, SEM -r)
juniper
  > qual shell eu uso?              # espera: ZSH
  > como devo indentar?             # espera: tabulação
  > que framework PHP o projeto X usa?   # espera: Laravel 11 (por significado)
  > /sair

# 3. atualização
juniper
  > migrei o X para o Laravel 12
  > /sair
juniper memory list --all      # a de Laravel 11 deve estar "superseded"
juniper "que framework o projeto X usa?"   # espera: Laravel 12

# 4. esquecer
juniper "esquece o que eu disse sobre o projeto X"   # ela lista e pergunta; responda "sim"
juniper memory list --all      # nada do projeto X, nem a versão antiga
juniper "que framework o projeto X usa?"   # espera: não lembra

3. O que conferir (e o que fazer se falhar)

SintomaOnde olhar
Não guardou nada, ou guardou lixoA extração depende do LLM. juniper memory list mostra o que entrou. O prompt está em brain/memory/extraction.py; apague o que não presta com juniper memory forget <id>.
Guardou, mas não lembra na sessão 2Quase sempre o retrieval.threshold (0.80, um palpite). Rode juniper memory search "que framework PHP o projeto X usa" --threshold -1: ele mostra a nota de cada memória. Ponha o corte entre a menor nota do que é relevante e a maior do que não é, no config.yaml.
Traz memória que não tem a verO mesmo: suba o threshold.
Criou duplicata ou não substituiu a versão antigaÉ o "juiz" do LLM (duplicate/supersede) ou o extraction.neighbor_threshold (0.75) que não considerou as duas parecidas. Veja a nota com memory search.
Nada foi extraído ao fecharCtrl+C não extrai: use /sair ou Ctrl+D. Confira também memory.session.store: mongo e memory.extraction.enabled: true.

Há também um teste com o modelo real de embeddings que imprime as notas das perguntas do marco e confere que o modelo separa o relevante do irrelevante: pytest -m integration -s tests/test_acceptance_sprint2.py (baixa ~120 MB).

4. Limitações conhecidas

A Sprint 2 só se considera encerrada depois do roteiro manual passar na sua máquina: o teste automatizado usa um LLM e um modelo de embeddings simulados.

Parâmetros ainda não calibrados: retrieval.threshold (0.80), extraction.neighbor_threshold (0.75) e os prompts de extração e de julgamento.

Latência real e sob carga (embedding da pergunta + leitura dos vetores no MongoDB a cada mensagem) não foi medida.
