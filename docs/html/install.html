Guia de instalação

Como instalar a Juniper e todas as dependências de desenvolvimento, a partir de uma máquina limpa. Não precisa ter Python instalado e nada é instalado no sistema: tudo fica dentro de ~/.juniper, num ambiente virtual.

1. Instalação rápida

Você precisa só de git, bash e curl (ou wget).

git clone git@github.com:petrusnog/juniper.git ~/.juniper
bash ~/.juniper/scripts/install.sh

No final aparece "Juniper instalada e pronta para uso". Abra um terminal novo e rode:

juniper

Depois da primeira instalação o comando também existe dentro do shell: juniper install faz o mesmo (veja a seção 4).

Durante a instalação ela pede só uma coisa que não tem como descobrir sozinha: as chaves dos LLMs: DeepInfra, o cérebro principal (deepinfra.com/dash/api_keys), e Groq, o plano B grátis (console.groq.com/keys). Cole e pronto; Enter pula, e você pode colocar depois em ~/.juniper/.env.

Depois ela pede o caminho da chave da conta de serviço do GCP (arquivo .json com qualquer nome). Ela cria a pasta ~/.juniper/certs/, valida a chave e a salva como certs/gcp-key.json. Ainda não tem a chave? Siga a seção 7. Conta de serviço no GCP e rode o instalador depois (ou use --gcp-key).

Para ler este guia a qualquer momento: juniper docs e acesse http://localhost:47831 (veja a seção 10).

Python: sem Python na máquina

O instalador procura um Python 3.11+ que consiga criar ambientes virtuais. Se achar, usa. Se não achar (ou se for um Python incompleto, como o do Ubuntu sem python3-venv), baixa o uv com verificação de checksum e usa-o para baixar um Python 3.12 isolado. Os dois ficam em ~/.juniper/.tools/, sem root e sem tocar no que já existe.

Rodar o instalador de novo é seguro: numa instalação saudável ele só confirma ("nada a fazer") em poucos segundos.

Falhas de rede

Cada download e instalação é tentado até 3 vezes. Se mesmo assim falhar, a mensagem diz a causa em português (por exemplo, "sem conexão com a internet") e o detalhe técnico fica em ~/.juniper/logs/install.log. O instalador só termina com sucesso se o teste final passar.

4. Opções

OpçãoEfeito
--devInstala também pytest, pytest-asyncio, ruff e mypy.
--checkSó verifica e diz se está saudável; não altera nada.
--cleanApaga o ambiente e instala do zero.
--yesSem perguntas (scripts e CI).
--no-rcNão altera ~/.zshrc nem ~/.bashrc.
--gcp-key=CAMINHOInforma a chave de conta de serviço do GCP sem perguntar (qualquer nome de arquivo); é copiada para certs/gcp-key.json.
juniper install --dev          # dentro do shell (zsh), ou:
juniper install --check        # pelo binário Python
bash ~/.juniper/scripts/install.sh --dev

5. Ambiente de desenvolvimento

bash ~/.juniper/scripts/install.sh --dev
source ~/.juniper/.venv/bin/activate

pytest tests/ -v          # testes (não usam rede nem chave real)
ruff check brain/ tests/  # lint
mypy brain/               # tipos (strict)

Uma task só está pronta quando os três passam (Definition of Done em docs/JUNIPER.md).

Sem o instalador (manual)

python3 -m venv ~/.juniper/.venv
~/.juniper/.venv/bin/pip install -e "~/.juniper[dev]"
cp ~/.juniper/config.yaml.example ~/.juniper/config.yaml
cp ~/.juniper/.env.example ~/.juniper/.env      # preencha JUNIPER_GROQ_API_KEY

6. O que é alterado na sua máquina

OndeO quê
~/.juniper/.venv/Ambiente virtual com as dependências.
~/.juniper/.tools/uv e Python isolado (só se não havia Python utilizável).
~/.juniper/config.yaml, .envConfiguração (o .env fica com permissão 600).
~/.juniper/certs/gcp-key.jsonChave da conta de serviço do GCP (pasta com permissão 700, arquivo 600; fora do git).
~/.local/bin/juniperAtalho para o executável.
~/.zshrcLinha que carrega os comandos do shell (search, deploy...). Troca a linha antiga ~/.juniper/juniper.sh pela nova.
~/.zshrc, ~/.bashrcInclui ~/.local/bin no PATH, se ainda não estiver.
~/.juniper/logs/Log da instalação e os logs de uso.

Antes de alterar um arquivo de shell, o instalador guarda uma cópia ao lado dele (.zshrc.juniper.bak). Para desfazer tudo: bash ~/.juniper/scripts/uninstall.sh.

7. Conta de serviço no GCP

A Juniper usa uma conta de serviço do Google Cloud para falar com a agenda. Passo a passo no console:

7.1 Projeto

Acesse console.cloud.google.com, abra o seletor de projetos (topo da página) e escolha um projeto ou crie um novo. Confirme que ele está ativo antes de continuar.

7.2 Ativar a API

Menu ☰ → APIs e serviços → Biblioteca, procure Google Calendar API e clique em Ativar.

7.3 Criar a conta de serviço

Menu ☰ → IAM e administrador → Contas de serviço → + Criar conta de serviço. Dê um nome (ex.: juniper) e clique em Criar e continuar. Não é preciso conceder papel de projeto para usar a agenda: o acesso é dado compartilhando a agenda com o e-mail da conta (veja T-022). Clique em Concluir.

7.4 Gerar a chave JSON

Na lista, abra a conta criada → aba Chaves → Adicionar chave → Criar nova chave → tipo JSON → Criar. O navegador baixa um arquivo como meu-projeto-a1b2c3.json; essa é a única vez que a chave aparece. Informe o caminho dele ao instalador: o nome pode ser qualquer um.

7.5 Conferir

ls -l ~/.juniper/certs/gcp-key.json    # -rw------- (600)
python scripts/check_google.py
SegurançaA chave dá acesso à conta de serviço. Nunca a versione no git (certs/ já está no .gitignore), não a envie por chat ou e-mail e apague o arquivo baixado depois de instalar. Se vazar, exclua a chave na aba Chaves e gere outra.cuidado

8. Opcionais

Ollama (reserva local, o último da fila). Instale em ollama.com e rode ollama pull llama3.1. A Juniper usa quando a DeepInfra e a Groq falham.

Agenda do Google. Precisa de conta de serviço e agenda própria; a chave se gera na seção 7 e o restante está na página T-022. Valide com python scripts/check_google.py.

9. Se algo der errado

"Faltam curl ou wget"Só acontece sem Python na máquina: instale um deles (sudo apt install curl) e rode de novo.1 comando
"Sem conexão com a internet"Conecte-se e rode de novo; o que já foi instalado é reaproveitado.repetir
juniper: command not foundAbra um terminal novo (o PATH foi ajustado agora). Se persistir: ~/.local/bin/juniper version.novo terminal
Algo estranho no ambientejuniper install --clean recria tudo e é seguro.--clean
"Chave inválida: o JSON não é de uma conta de serviço"Você apontou para outro tipo de credencial. Gere uma chave JSON em Contas de serviço (seção 7.4) e rode install.sh --gcp-key=CAMINHO.refazer
Qualquer outra falhaO detalhe técnico está em ~/.juniper/logs/install.log.log

10. Ler esta documentação

juniper docs

Serve este livro de bolso localmente; abra http://localhost:47831 no navegador (a Juniper não abre o navegador sozinha). Ctrl+C encerra. Se a porta 47831 estiver ocupada, a Juniper usa a próxima livre (47832, 47833...) e mostra o endereço certo no terminal.
