Contexto

A Juniper falava com dois LLMs: Groq (nuvem, primário) e Ollama (local, reserva). Na prática, o limite do plano gratuito da Groq e o Ollama em CPU (lento, com pouca RAM) deixaram a experiência frágil: quando a Groq cai, o fallback leva minutos para o primeiro token.

A DeepInfra oferece uma API compatível com a da OpenAI (https://api.deepinfra.com/v1/openai), com streaming SSE e tool calling, o que encaixa no contrato LLMProvider sem mudar o resto do cérebro.

Decisão

1. Novo provider DeepInfraProvider (brain/llm/deepinfra_provider.py)

  • Implementa o mesmo contrato dos outros (chat, stream, health_check), com os erros tipados de brain/llm/errors.py.
  • Sem SDK: usa httpx (já é dependência). A superfície é pequena (um endpoint) e o transporte fica injetável nos testes (httpx.MockTransport).
  • Autenticação: Authorization: Bearer, chave em JUNIPER_DEEPINFRA_API_KEY (.env). Resolvida de forma preguiçosa: sem chave, o provider existe, mas a primeira chamada levanta LLMAuthError e o router segue adiante.
  • Streaming: linhas SSE data: {...} até data: [DONE]. Tool calls podem chegar fragmentadas e são acumuladas por index (se o índice faltar, um fragmento com id abre uma chamada nova). O usage pode vir no chunk final ou num chunk à parte; os dois casos são tratados.
  • Mapeamento de erros HTTP:
HTTPErroFailover
401, 402, 403LLMAuthError (chave inválida ou sem crédito)sim
429LLMRateLimitErrorsim
5xx, conexão, stream cortadoLLMUnavailableErrorsim
timeoutLLMTimeoutErrorsim
demais 4xxLLMError (com trecho do erro, sem a chave)não: repetiria igual
  • Modelo padrão: deepseek-ai/DeepSeek-V4-Flash-0731, o usado nos exemplos de tool calling da própria documentação. É configurável (llm.deepinfra.model); precisa suportar tool calling.

2. Nova ordem de prioridade

llm.priority: [deepinfra, groq, ollama]

DeepInfra primeiro; se cair, Groq; se cair, o modelo local. É o novo padrão do código e do config.yaml.example. Quem já tem config.yaml precisa atualizar a linha priority (o arquivo local vence o padrão do código).

3. Prompt compacto continua só no local

Somente o Ollama (CPU) recebe a persona curta e as descrições de tool enxutas (compact_prompt). DeepInfra e Groq recebem o prompt completo.

Consequências

  • Uma chave a mais no .env (o instalador pergunta; Enter pula). Sem a chave, o failover simplesmente começa na Groq.
  • Os avisos de failover (A DeepInfra recusou as credenciais. Vou tentar a Groq.) e as dicas de erro passam a citar o provider certo.
  • O log estruturado mascara também a chave da DeepInfra.
  • Se a DeepInfra mudar o formato de erro ou de stream, só deepinfra_provider.py e seus testes mudam.
  • Não validado ao vivo neste ADR: os testes usam transporte HTTP falso; a primeira chamada real depende da chave do Petrus.
