API HTTP pronta

As rotas HTTP do cérebro: a saúde do servidor, o download do app Android e a API de leitura do dashboard, com autenticação, paginação, filtros e códigos de resposta.

O cérebro expõe dois servidores HTTP no mesmo processo (juniper serve): o do WebSocket, que também responde /health, e o do dashboard, com uma API JSON somente leitura. Para conversar, tocar ferramentas ou mexer na memória, use a API WebSocket.

Saúde do cérebro

GET /health na porta do WebSocket, sem autenticação. É o que o healthcheck do Docker e o deploy usam.

curl -s http://127.0.0.1:8765/health
{ "status": "ok", "memory": "ready", "version": "4.0.0" }
status / memorySignificado
ok / readyTudo pronto.
ok / offPronto, sem memória de longo prazo.
degraded / warming_upO modelo de embeddings ainda está carregando (ou baixando, na primeira vez). A conversa funciona sem memória. Continua HTTP 200, para o contêiner não ser reiniciado.

Qualquer outro caminho que não /health, /v1/ws, /app/update ou /app/update/apk responde 404.

Atualização do app

Na porta do WebSocket, o cérebro serve o APK do app Android (ADR-026). As duas rotas exigem Authorization: Bearer <token dos clientes> (sem ele ou com token errado: 401) e só leem a pasta app_update.dir (Configuração).

RotaResposta
GET /app/update200 com a versão publicada, ou {"available": false} se não há nada válido.
GET /app/update/apk200 com o arquivo (application/vnd.android.package-archive); 404 se não há versão publicada. Cada download vira um evento app_update no log.
curl -s -H "Authorization: Bearer $(cat .juniper-dev/state/token)" http://127.0.0.1:8765/app/update
{ "available": true, "version_code": 321, "version_name": "0.1.321", "sha256": "…", "size": 61234567, "released_at": "2026-10-29T12:00:00Z" }

Uma publicação só é oferecida se o latest.json e o APK existem e o tamanho do arquivo bate com o size (um envio pela metade nunca é servido). Como publicar: Clientes em produção.

Dashboard

Todas as rotas aceitam só GET (outro método: 405). O cabeçalho Host precisa ser um IP, localhost, um nome *.ts.net ou um host de dashboard.allowed_hosts; senão, 421.

Autenticação

RotaAutenticaçãoO que faz
GET /healthnenhuma{"ok": true, "service": "dashboard"}
GET /loginnenhumaA página de login.
GET /api/loginAuthorization: Bearer <token>Confere o token dos clientes e devolve o cookie de sessão (HttpOnly, SameSite=Strict, Secure se X-Forwarded-Proto: https), válido por dashboard.session_hours. Token errado: 401; cinco erros em cinco minutos: 429.
GET /api/logoutnenhumaApaga o cookie.
GET /api/...cookie de sessão ou Authorization: Bearer <token>As rotas de dados abaixo. Sem credencial: 401 {"error": "faça login"}.

Para scripts, o cabeçalho Authorization basta:

curl -s -H "Authorization: Bearer $(cat .juniper-dev/state/token)" http://127.0.0.1:8766/api/overview

Convenções

  • Respostas em JSON UTF-8, Cache-Control: no-store.
  • Paginação nas listas: ?limit= (padrão 50, máximo 200) e ?offset=; a resposta traz {"total", "offset", "limit", "items"}.
  • Segredos mascarados e vetores removidos de tudo o que sai.
  • Erros: {"error": "<motivo>"} com 404 (rota ou id inexistente) ou 503 (a camada está desligada: memória de longo prazo ou Memória V2, com o motivo).
  • Nenhuma rota escreve no banco.
