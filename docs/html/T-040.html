T-040 — CLI de chat

A primeira forma de conversar com a Juniper de verdade. Um cliente fino: lê o que você digita, mostra a resposta chegando token a token e pergunta [y/N] quando uma tool precisa da sua confirmação. Toda a lógica continua em brain/core. Arquivo: brain/clients/cli.py.

1. Uso

Uma mensagem

juniper chat "o que tenho amanhã?"

Responde e sai. Código de saída 1 se nenhum LLM respondeu.

Conversa (REPL)

juniper chat
você> oi
juniper> ...
você> /sair

/sair, /exit ou Ctrl+D encerram. Ctrl+C também.

juniper chat --provider ollama "oi"    # força um provider, sem failover
python -m brain chat                    # equivalente, sem instalar

2. Como funciona

PeçaO que faz
chatComando do Typer. Monta o router, o Dispatcher e o Agent da T-030 e chama converse.
converseUm turno (mensagem única) ou um laço de turnos (REPL). Erros de LLM são mostrados sem derrubar o REPL.
PrinterImprime cada token assim que chega, sem interpretar colchetes como markup do rich (uma resposta com [bold] sai literal).
make_confirmCria o callback de confirmação do dispatcher: mostra a tool e os argumentos e pergunta Confirma? [y/N]. Tool DESTRUTIVA mostra IRREVERSÍVEL em vermelho.
LineReaderLê o teclado numa thread, sem travar o event loop.
friendly_errorTraduz falhas do LLM em instruções em PT-BR.

3. Confirmação com timeout

O tempo limite (tools.security.confirmation_timeout, 60s) é aplicado pelo dispatcher; o CLI só pergunta. Respostas aceitas como "sim": y, yes, s, sim. Qualquer outra coisa, Enter vazio, Ctrl+D ou o tempo esgotado = não.

input() não pode ser cancelado. Quando o tempo esgota, a thread de leitura continua esperando; o próximo pedido de leitura reaproveita essa mesma thread em vez de abrir outra (duas threads disputariam a mesma linha). A thread é daemon, então nunca impede o programa de fechar.

4. Erros em PT-BR

chave Groq ausente ou inválida"Groq sem chave válida: defina JUNIPER_GROQ_API_KEY no arquivo .env."dica
limite da Groq (429)"Limite da Groq atingido: espere um minuto e tente de novo."dica
Ollama fora do ar ou lento"Ollama não respondeu: ele está rodando? (ollama serve)"dica
--provider inválidoRecusado antes de qualquer trabalho, listando os válidos.exit ≠ 0

Abaixo da dica vem o detalhe técnico em cinza, para depuração.

5. Decisões proativas

#DecisãoPor quê
1--provider monta um router com um único provider."Forçar" significa sem failover: útil para testar o Ollama sem a Groq responder no lugar.
2No REPL, erro de LLM não encerra nem muda o código de saída.A sessão é interativa; só a mensagem única devolve exit 1.
3Dependências injetáveis (build_router, leitor de linhas).Os testes rodam o CLI inteiro com um provider falso, sem rede nem teclado.
4Sem indicador das tools de leitura (READ).O Agent ainda não avisa o cliente sobre cada tool; só as que pedem confirmação aparecem. Fica para quando o log (T-031) existir.

6. Limitações conhecidas

Resposta em texto puro. Os tokens saem como chegam; não há renderização de Markdown (a persona já evita Markdown fora de código).

Ctrl+C encerra o programa mesmo no meio de uma resposta; ainda não cancela só o turno.

Sem histórico entre execuções. A conversa vive só enquanto o REPL está aberto.

Se a confirmação expirar, a pergunta antiga continua na tela até você digitar algo; a próxima linha digitada responde a ela.

7. Como testar

pytest tests/test_cli.py -v

Cobre: versão, mensagem única com streaming, colchetes literais, REPL até /sair e até EOF, --provider inválido e válido, chave Groq ausente (instrução do .env, exit 1), REPL sobrevivendo a erro de LLM, dicas de friendly_error, respostas do [y/N], aviso de IRREVERSÍVEL, o reaproveitamento da thread após timeout e um fluxo completo com confirmação negada.

Para ver ao vivo, com a chave no .env: juniper chat "marca um teste amanhã às 10h".
