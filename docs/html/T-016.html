T-016 — DeepInfraProvider

O novo LLM principal na nuvem. Fala com a API da DeepInfra (compatível com a da OpenAI) e entra na frente da fila do failover: DeepInfra → Groq → Ollama. Arquivo: brain/llm/deepinfra_provider.py. Decisão registrada em docs/decisions/ADR-009.md.

1. A nova ordem do failover

DeepInfranuvem · principal
→ se cair →
Groqnuvem · segunda opção
→ se cair →
Ollamalocal · reserva

Quando um provider falha, a Juniper avisa na conversa ("A DeepInfra recusou as credenciais. Vou tentar a Groq.") e segue com a mesma conversa no próximo. A ordem vem de llm.priority no config.yaml.

2. Configuração

.env (segredo)

JUNIPER_DEEPINFRA_API_KEY=...

Crie em deepinfra.com/dash/api_keys. O juniper install pergunta a chave; Enter pula.

config.yaml

llm:
  priority: [deepinfra, groq, ollama]
  deepinfra:
    model: deepseek-ai/DeepSeek-V4-Flash-0731
    timeout: 30

O modelo precisa suportar tool calling.

Atenção: se você já tinha um config.yaml, a linha priority dele vence o padrão do código. Atualize para [deepinfra, groq, ollama]. Sem a chave da DeepInfra a Juniper não quebra: o provider falha com "chave ausente" e o router começa pela Groq.

juniper chat -p deepinfra "oi"     # força só a DeepInfra, sem failover

3. Como fala com a API

ItemValor
EndpointPOST https://api.deepinfra.com/v1/openai/chat/completions
AutenticaçãoAuthorization: Bearer <chave>
StreamingSSE: linhas data: {...} até data: [DONE]; texto em choices[0].delta.content
Toolstools + tool_choice: "auto"; os argumentos voltam como string JSON e são convertidos em dicionário
Uso de tokensNo chunk final (ou num chunk à parte); os dois formatos são aceitos
SaúdeGET /models (falso se não há chave)

Não usa SDK: só httpx, que já é dependência. Tool calls que chegam em pedaços são montadas por index, e se a API omitir o índice, um pedaço com id abre uma chamada nova.

4. Erros e failover

401 · 402 · 403Chave inválida, ausente ou sem crédito. O provider fica inutilizável.LLMAuthError → próximo
429Limite de requisições ou modelo ocupado.LLMRateLimitError → próximo
5xx · conexão · stream cortadoFora do ar ou instável.LLMUnavailableError → próximo
timeoutPassou de llm.deepinfra.timeout.LLMTimeoutError → próximo
outros 4xx (ex.: 400, 422)Pedido inválido: repetir em outro provider daria igual. A mensagem traz um trecho do erro, sem a chave.LLMError, sem failover

A chave nunca aparece em mensagens de erro, nem no log estruturado (que mascara também a chave configurada).

5. Decisões proativas

#DecisãoPor quê
1402 conta como erro de credencial.Sem saldo o provider não serve, e o failover resolve na hora.
2Não envia stream_options.A documentação da DeepInfra não o menciona e um campo desconhecido poderia gerar 400.
3O prompt completo vai para a DeepInfra; o compacto continua só no Ollama.Na nuvem a leitura do prompt é rápida; o compacto existe por causa da CPU local.
4Modelo padrão = o dos exemplos de tool calling da doc.É o que a própria DeepInfra mostra funcionando com tools. Troque em config.yaml se preferir outro.

6. Limitações conhecidas

Ainda não testado ao vivo. Os testes usam um transporte HTTP falso; a primeira chamada real depende da sua chave. Depois de colocá-la, rode python scripts/healthcheck.py --live.

Formato dos erros 4xx. A DeepInfra não documenta o corpo dos erros; o provider tenta error, detail e message e, se nada servir, mostra "sem detalhes".

Sem controle de custo. Nenhum limite de tokens ou gasto é imposto; vale acompanhar o painel da DeepInfra.

7. Como testar

pytest tests/test_deepinfra_provider.py -v

Cobre: chat com autenticação e payload, tools e tool_choice, argumentos JSON (válidos, vazios e inválidos), respostas malformadas, streaming com e sem usage final, tool calls fragmentadas (com e sem index), ruído SSE, erro no meio do stream, stream cortado, mapeamento de cada status HTTP, formatos de corpo de erro sem vazar a chave, timeout, conexão recusada, chave ausente sem chamar a API e health_check.
