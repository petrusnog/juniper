T-031 — Logging estruturado

Tudo que a Juniper faz fica registrado: cada chamada ao LLM, cada tool, cada failover e cada erro. Uma linha JSON por evento, um arquivo por dia, com segredos mascarados. Arquivo: brain/eventlog.py.

1. Onde fica

~/.juniper/logs/2026-10-11.jsonl      # um arquivo por dia, permissão 600

tail -f ~/.juniper/logs/$(date +%F).jsonl | jq .     # acompanhar ao vivo

Cada linha tem ts (com fuso), run (id curto: agrupa os eventos de uma execução do CLI) e event, mais os campos do evento.

2. Eventos

EventoQuandoCampos principais
llm_requestAntes de cada chamada ao LLMmessages, tools (quantidades)
llm_responseQuando a resposta terminaprovider (quem respondeu), latency_ms, usage, finish_reason, tool_calls (nomes)
tool_callDepois de cada tool pedidaname, tier, args, decision, success, output/error, duration_ms
failoverUm provider falhou e o próximo assumiuprovider, type, message
errorFalha do LLM no turno ou tool que quebrouwhere, type, message

Valores de decision em tool_call:

autoTool de leitura, executou direto.
confirmedPediu confirmação e você disse sim.
deniedVocê negou, o tempo esgotou ou não havia como perguntar.
forbidden · unknown · invalidTool proibida, nome inventado pelo LLM, ou argumentos errados.
precheck_failedA tool recusou antes de te perguntar (ex.: conflito na agenda).
crashedA tool levantou exceção (também gera um error).

3. Segredos

Nada vai para o disco sem passar por redact().

O queResultado
Campos com nome api_key, token, secret, password, authorization, private_key"***". Contadores como prompt_tokens são preservados.
Textos com gsk_…, Bearer … ou blocos de chave privadaTrecho trocado por ***.
A chave da Groq configurada, onde quer que apareça***.
Textos com mais de 2000 caracteresCortados, com a contagem do que sobrou.

O que você digita não é gravado (só quantidades), mas a saída das tools é: um git_search grava os commits que achou. Por isso o arquivo é criado com permissão 600.

4. Decisões proativas

#DecisãoPor quê
1O log fica em brain/eventlog.py, fora de core/.Router (camada LLM), dispatcher e agente o usam; assim nenhuma camada depende de outra só por causa do log.
2Logar nunca derruba a Juniper.Disco cheio ou pasta sem permissão simplesmente pulam o evento.
3Não grava a sua mensagem nem a resposta do LLM, só tamanhos e contagens.Privacidade por padrão. Para depurar a conversa, o campo pode ser adicionado depois, com opt-in.
4Os testes nunca escrevem no log real (tests/conftest.py).Evita poluir ~/.juniper/logs a cada pytest.

5. Limitações conhecidas

Sem rotação nem limpeza. Um arquivo por dia; apagar os antigos é manual.

O juniper.log do shell é outro. Os comandos legados continuam gravando o texto simples de sempre em ~/.juniper/juniper.log.

Sem modelo no llm_response. O streaming dos providers não informa o modelo; só o provider.

6. Como testar

pytest tests/test_eventlog.py -v

Cobre mascaramento (chaves, valores, chave configurada, contadores de token), arquivo por dia com permissão 600, log que nunca levanta erro, e os ganchos: eventos do agente, cada decision do dispatcher, erro de tool, erro de LLM e failover do router.
