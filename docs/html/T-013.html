T-013 — GroqProvider

Provider primário: implementa o contrato LLMProvider (T-011) falando com a nuvem da Groq pelo SDK oficial groq. Arquivo: brain/llm/groq_provider.py.

1. O que ele faz

Irmão do OllamaProvider: mesma interface, outro "idioma". A Groq fala o formato OpenAI, então a ida é direta (Message.to_openai()); o trabalho está em ler a volta e traduzir os erros do SDK.

chat(messages, tools)vocabulário Juniper
→
to_openai()já é o formato da Groq
→
AsyncGroqchat.completions.create
→
LLMResponseMessage + TokenUsage

Exceções do SDK viram LLM*Error tipado (seção 4).

2. Configuração e uso

Construtor

  • api_key: padrão settings.groq_api_key (JUNIPER_GROQ_API_KEY no .env)
  • model: padrão settings.llm.groq.model (llama-3.3-70b-versatile)
  • timeout: padrão settings.llm.groq.timeout (30 s)
  • client: só para testes (cliente falso)

Exemplo

p = GroqProvider()
r = await p.chat([
  Message("user", "oi")
])
print(r.message.content)
await p.aclose()

Use aclose() ao terminar para fechar a conexão HTTP.

4. Erros

O provider nunca deixa vazar exceção do SDK: tudo vira um tipo da T-011. A ordem dos testes importa, porque APITimeoutError é filho de APIConnectionError; o timeout é checado primeiro.

chave ausenteSem JUNIPER_GROQ_API_KEY. Lançado na primeira chamada, não no construtor.LLMAuthError
AuthenticationError / PermissionDeniedErrorHTTP 401/403: chave inválida ou sem permissão.LLMAuthError
RateLimitErrorHTTP 429.LLMRateLimitError
APITimeoutErrorPassou do timeout.LLMTimeoutError
APIConnectionError / InternalServerErrorSem rede, DNS, ou 5xx.LLMUnavailableError
outros 4xx (ex.: 400, 404)Erro de pedido ou de modelo: configuração, não disponibilidade.LLMError
sem choices / tool sem nome / JSON inválidoResposta fora do esperado.LLMError

5. Segurança da chave

A chave é um SecretStr nas settings e só é "aberta" na hora de criar o cliente. As mensagens de erro são montadas por nós (código HTTP + trecho curto), nunca copiando o str(exc) do SDK. Se o corpo do erro ecoar a chave, ela é trocada por ***. A exceção original é suprimida (from None), então a chave também não aparece no encadeamento do traceback. Há um teste que verifica isso.

6. health_check e stream

health_check()

Chama models.list(). Devolve True se respondeu. Chave ausente ou qualquer erro do SDK vira False, sem lançar exceção. Consome uma requisição da cota.

stream()

Implementado na T-014: usa stream=True do SDK e monta as tool calls fragmentadas. Veja T-014.

7. Decisões proativas (tomadas sem consultar você)

O briefing deixava estes pontos em aberto. Escolhi o que recomendo; cada um é fácil de reverter.

#DecisãoPor quê
1Chave ausente falha na primeira chamada, não no construtor.O router (T-015) instancia todos os providers de llm.priority. Se o construtor lançasse, um .env sem chave derrubaria o boot em vez de cair para o Ollama. A spec do router já prevê failover em LLMAuthError.
2max_retries=0 no SDK (o padrão é 2).Retry e failover são responsabilidade do router. Com retries internos, uma Groq fora do ar seguraria o usuário por vários timeouts antes de cair para o Ollama.
3Cliente do SDK criado sob demanda (lazy) e injetável pelo parâmetro client.Consequência da decisão 1, e permite testar sem rede nem mock global.
4Mensagens de erro próprias, sem repassar o texto do SDK.Garante o aceite "chave nunca aparece em logs/exceções". Custo: perde-se parte do detalhe do erro original.
5403 (PermissionDeniedError) também é LLMAuthError.A spec listava só AuthenticationError, mas a hierarquia da T-011 documenta "401/403" para este erro.
6Outros 4xx viram LLMError genérico (sem failover).Mesmo critério do Ollama: 400/404 indicam erro de pedido ou modelo, e outro provider não resolve.
7Testes com cliente falso (FakeClient) em vez de httpx.MockTransport.A spec pede "cliente SDK mockado". Os erros do SDK são construídos de verdade (groq.RateLimitError etc.), então o mapeamento é testado de ponta a ponta.
8Sem ajuste em config.py, ADRs ou demais providers.Escopo mínimo. Observação: ollama_provider.py:94 tem um aviso do mypy strict (no-any-return), anterior a esta task.

8. Como testar

Automatizado (sem rede)

pytest tests/test_groq_provider.py -v
Cobre texto, tool call, argumentos inválidos, histórico de tools, todos os mapeamentos de erro, chave ausente, vazamento da chave, health_check e aclose. Não precisa de chave nem de internet.

Manual (Groq real)

export JUNIPER_GROQ_API_KEY=gsk_...
python - <<'EOF'
import asyncio
from brain.llm.groq_provider import GroqProvider
from brain.llm.types import Message
async def main():
    p = GroqProvider()
    r = await p.chat([Message("user", "oi")])
    print(r.message.content, r.usage)
    await p.aclose()
asyncio.run(main())
EOF
Não foi executado nesta task: o ambiente de desenvolvimento não tem chave nem acesso à Groq.

9. Limitações conhecidas

Streaming disponível desde a T-014.

Sem teste contra a API real. O mapeamento de erros foi validado com as exceções reais do SDK (v1.7.0), mas o comportamento da Groq em produção (formato exato de erros, limites do tier gratuito) ainda precisa de uma chamada de verdade.

Limite do tier gratuito: a Groq limita requisições e tokens por minuto. O LLMRateLimitError existe para o router cair para o Ollama nesse caso.

Sem retry próprio: uma falha transitória de rede vira erro imediato. É intencional (decisão 2).
