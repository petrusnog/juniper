T-061 — Perfil do usuário

A Juniper passa a saber quem você é desde a primeira palavra: um parágrafo de identidade (nome, nascimento, nacionalidade) vai em toda mensagem, sem depender de a busca achar algo parecido. É o que faz "bom dia" ser respondido com o seu nome. Arquivos: brain/memory/profile.py, brain/memory/retrieval.py, brain/memory/extraction.py e brain/tools/memory.py. Decisões de fundo no ADR-011 (seção 8).

1. O que ela guarda

O usuário se chama Petrus Rennan, é um homem adulto de {idade} anos,
nascido em 16/06/1999, brasileiro.

Um parágrafo de até 500 caracteres (memory.profile.max_chars) mais campos estruturados: nome, data de nascimento, nacionalidade e gênero (este só se você disser; ela nunca deduz).

A idade não fica escrita. O texto guarda {idade} e a idade é calculada da data de nascimento a cada mensagem: o mesmo perfil diz 27 anos hoje e 28 depois do seu aniversário, sem ninguém reescrever nada. Se a data de nascimento não é conhecida, a Juniper simplesmente omite a idade.

Fica fora das memórias gerais: collection profile, um documento só. O perfil é a identidade; sentimentos e personalidade continuam como memórias.

2. Como entra no prompt (e quanto custa)

PeçaO que faz
Em toda mensagemO bloco <perfil> entra sempre, sem busca. Por isso a Juniper sabe seu nome mesmo num "bom dia".
CustoSó o parágrafo: no teto de 500 caracteres são ~150 tokens por mensagem. O limite vale ao gravar e ao injetar (um perfil maior que o limite é cortado). Sem perfil, nada entra.
PosiçãoLogo depois da persona, que é a parte estável do prompt: os providers reaproveitam o cache dela, já que o perfil muda raramente. As memórias relevantes continuam antes da sua mensagem.
SegurançaRotulado como dado, não instrução; o texto é limpo (uma linha, sem < e >), então não forja o bloco.

3. Como ela atualiza

Ao fechar o chat, a mesma chamada que extrai as memórias (T-056) recebe o perfil atual e a data. Ela só devolve um perfil novo se a conversa trouxe um dado de identidade novo ou corrigido; senão o perfil não muda e não há chamada extra ao LLM. Quando atualiza, avisa: "Atualizei o seu perfil."

O que a protege: só vale o que você escreveu (nunca saída de ferramenta ou página da web); passa pelo filtro de segredos e de "ordem para uma IA"; documentos (CPF, RG, CNH, passaporte) são recusados; texto maior que o limite ou data de nascimento inválida mantêm o perfil antigo.

Para valer na hora, sem esperar o fim do chat: diga "meu nome é Petrus Rennan" e a tool update_profile grava na hora, sem perguntar (T-062). Para conferir ou desfazer: juniper memory profile.

4. Memórias ligadas a você

A extração agora escreve o seu nome como sujeito e uma data absoluta no que for datado, para a memória ficar ligada a você e ser achada por significado:

Antes:  "Ficou frustrado com a pressão no trabalho hoje."
Agora:  "Petrus se sentiu frustrado em 14/10/2026 por uma pressão no trabalho."

Sem nome no perfil, o sujeito é "O usuário". Sentimentos e acontecimentos pessoais são sensíveis (o trecho vai ao provider do chat na extração): memory.extraction.save_feelings: false desliga.

5. Comandos

juniper memory profile                      # mostra o perfil (como a Juniper o lê hoje)
juniper memory profile set "O usuário se chama ..." \
    --name "Petrus Rennan" --birth-date 1999-06-16 --nationality brasileira
juniper memory profile forget [--yes]       # apaga só o perfil
juniper memory export                       # agora traz {"profile": ..., "memories": [...]}

No set, escreva {idade} onde iria a idade; os campos informados se somam aos que já existem.

6. Configuração

memory:
  profile:
    enabled: true
    max_chars: 500
  extraction:
    save_feelings: true

7. Limitações conhecidas

Depende do LLM de extração. Ele decide quando há dado de identidade novo e escreve o parágrafo; pode errar ou não perceber. Confira com juniper memory profile e corrija com set.

Fica em texto no seu MongoDB e vai ao provider do chat durante a extração, como o resto da conversa.

A regra "nome como sujeito e data absoluta" é uma instrução ao LLM: o código não a verifica memória por memória.

Só um usuário. Há um perfil por banco.

Não testado com LLM, banco e modelo reais; os testes usam simulados (inclusive o caso "bom dia" do teste de aceite).

8. Como testar

pytest -m "not integration"   # CI: sem LLM, sem banco, sem modelo
