T-058 — Tools de memória e juniper memory

Controle explícito da memória: você pede na conversa ("lembra que eu uso ZSH", "esquece o projeto X") ou usa o terminal para listar, buscar, apagar e exportar. Arquivos: brain/tools/memory.py, brain/clients/cli.py e brain/memory/longterm.py. Decisões de fundo no ADR-011.

1. Na conversa

ToolTierO que faz
rememberWRITE, sem confirmaçãoGuarda um fato que você pediu, na hora e sem perguntar (T-062). Passa pelas mesmas checagens e pela mesma deduplicação/atualização da extração automática (T-056): segredos, ordens e texto grande são recusados; repetir não duplica; uma versão nova substitui a antiga.
recallREADBusca por significado e devolve o que achou, com a nota de cada resultado.
forgetDESTRUCTIVEApaga de vez, por assunto (query) ou id. Mostra o que vai apagar e pede confirmação (ADR-006), e leva junto as versões antigas que a memória substituiu.

Guardar é silencioso; apagar pergunta. remember (e o update_profile da T-061) gravam sem pedir permissão, para a conversa fluir; quem quer ver ou mexer no que ela sabe usa juniper memory list, forget e profile. Já o forget é irreversível: a Juniper lista o que vai apagar ("esquecer para sempre: «O projeto X usa Laravel 12.»; ...") e só executa depois do seu "sim". Segredos, ordens e texto grande continuam recusados mesmo sem perguntar. O custo de não perguntar: algo plantado por uma página da web que o LLM leu pode virar memória; as memórias entram no prompt sempre como dado, nunca como ordem, e você as audita e apaga quando quiser.

As tools só aparecem para o LLM quando a memória de longo prazo está ligada (store: mongo e memory.extraction.enabled). Desligada, elas somem da lista.

2. No terminal

juniper memory list [--type preference|project|fact] [--all]
juniper memory search <termo...> [--limit N] [--threshold X]
juniper memory forget <id> [--yes]
juniper memory export [--vectors] [--output arquivo.json]
juniper memory reindex [--force]        # T-054

list: mais novas primeiro, com id, tipo, status, data e texto. --all inclui as superseded (só para auditoria).

search: mostra a nota de cada resultado. É a ferramenta para calibrar o memory.retrieval.threshold: --threshold -1 mostra a nota de tudo, e você vê onde fica o corte entre o que tem a ver e o que não tem.

forget: mostra o texto, pergunta "Pode apagar?" (padrão não) e apaga com as versões antigas. --yes pula a pergunta.

export: JSON com id, texto, tipo, status, origem e datas. Sem os vetores, a menos que você passe --vectors.

Todos precisam do MongoDB no ar; se não estiver, a mensagem diz o que fazer, sem stacktrace.

3. Limitações conhecidas

forget por assunto é por similaridade. Ele usa o mesmo top_k e threshold da busca, e apaga o que passar do corte. Por isso a Juniper lista tudo antes de pedir o "sim", e para algo preciso vale usar o id (recall ou juniper memory list mostram). Um corte baixo demais pode listar coisas que não têm a ver: confira a lista antes de confirmar.

"Sim" curto só vale para o que foi mostrado. Respostas longas ou condicionais ("só o primeiro") cancelam a ação e viram uma conversa normal (regra da T-051/ADR-006).

Não testado com LLM, banco e modelo reais. O comportamento do LLM ao escolher a tool e redigir a pergunta de confirmação foi simulado nos testes.

pytest -m "not integration"   # CI: sem LLM, sem banco, sem modelo
