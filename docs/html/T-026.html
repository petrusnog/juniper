T-026 · T-041 · T-042 — Comandos git (search e deploy)

Os comandos da v2 (search e deploy) continuam funcionando no terminal e agora a Juniper também os usa quando você pede em linguagem natural: "Juniper, busque os commits da feature 1339". Arquivos: shell/, brain/tools/juniper_cmds.py, brain/clients/cli.py.

1. Três jeitos de chamar o mesmo comando

Vocêjuniper search 1339
→
CLIT-041
→
shell/ (zsh)search_run, deploy_run
←
ToolT-026
←
Agente"busque a feature 1339"

A lógica continua nos scripts do shell/ (regra "shell é HMI, Python é cérebro" só no sentido de orquestrar). CLI e tools só chamam: zsh -c 'source shell/juniper.sh; _juniper_dispatch "$@"', com cada argumento separado. Nada passa por uma string de shell.

2. No terminal (T-041)

juniper search 4911 6531                         # commits com qualquer um dos termos
juniper deploy 4911                              # cherry-pick em develop e stage
juniper deploy 6531 --tasks 7432 --stage         # multi-task, só stage
juniper deploy 4911 11b81fb --hash               # um commit já existente

Os argumentos passam direto ao script, com terminal interativo (as perguntas de conflito e de criar branch funcionam como na v2). Também existem os nomes antigos grep, gitgrep e deployfeature, escondidos do --help. O código de saída do script é preservado.

3. Pelo agente (T-026)

git_search · READ

Parâmetro terms (lista). "Commits da feature 1339" vira terms=["1339"]. Roda direto, sem pedir confirmação. Devolve data, hash, mensagem e autor, sem cores. "Nenhum commit encontrado" é resposta, não erro.

git_deploy · DESTRUCTIVE

Parâmetros: feature_id, extra_tasks (opcional), target (both, develop ou stage). Faz push, então sempre pede [y/N] com aviso de irreversível.

As duas agem no repositório do diretório atual: rode juniper chat dentro do projeto. Fora de um repo git, a tool avisa em vez de falhar misteriosamente.

O que o git_deploy verifica antes de te perguntar

feature_id / extra_tasksSó dígitos. 13;rm ou $(x) são recusados.recusa
não é repositório gitAvisa e para.recusa
alterações não commitadasO deploy troca de branch; com arquivos modificados poderia dar conflito ou bagunça.recusa
nenhum commit feature(id)/hotfix(id)Não adianta pedir sua confirmação para um deploy vazio.recusa

Só o modo em lote é exposto ao agente. O modo "mensagem" (git add . + commit) e o --hash ficam apenas no terminal, onde você vê o que está acontecendo.

4. Sem terminal, sem travar

O script deploy pergunta coisas (criar branch? como resolver conflito?). Quando o agente o roda, não há ninguém para responder.

O comando roda com a entrada fechada e um tempo máximo (30 s no search, 5 min no deploy).

Branch inexistente: a pergunta recebe "fim da entrada", conta como "não" e a Juniper conta que a criação foi recusada. Crie a branch você mesmo ou rode juniper deploy no terminal.

Conflito no cherry-pick: aqui havia um bug no script (a pergunta repetia para sempre quando a entrada acabava). Corrigi: sem terminal, ele aborta o cherry-pick e volta à branch original.

5. Versões dos scripts

search.sh e deploy.sh (e o install.sh) vieram da origin/master, mais nova que a v4: search com vários termos, deploy com detecção de commits já presentes, --tasks e --develop/--stage.

Caminhos corrigidos. Os scripts procuravam ~/.juniper/commands e ~/.juniper/core, que na v4 ficam em shell/. Agora usam JUNIPER_SHELL_DIR (definido por shell/juniper.sh). Se o seu .zshrc faz source ~/.juniper/juniper.sh, troque para source ~/.juniper/shell/juniper.sh.

6. juniper tools (T-042)

Tabela com todas as tools registradas: nome, tier (colorido), locality e descrição. Útil para ver o que o agente tem à disposição.

7. Limitações conhecidas

Repositório = diretório atual. Não há parâmetro para apontar outro repo, de propósito (menos superfície de ataque).

Muito texto no deploy. A saída (cortada em 20 KB) volta inteira ao LLM, que gasta tokens para resumi-la.

Depende do zsh instalado, como a v2.

8. Como testar

pytest tests/test_juniper_cmds.py tests/test_cli.py -v

Os testes usam repositórios git temporários de verdade, sem rede: busca (sem cores, OU entre termos, sem resultado, metacaracteres literais, termos inválidos, fora de repo), validações do deploy, e um deploy completo contra um remoto local, inclusive rodá-lo duas vezes sem duplicar commits e a recusa de criar branch sem terminal. No CLI: repasse de argumentos, aliases escondidos, código de saída e a tabela de tools.

Ao vivo: cd seu-projeto && juniper chat "busque os commits da feature 1339".
