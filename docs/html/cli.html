CLI pronta

O comando juniper: chat, mensagem única, retomar conversa, comandos de memória, git e utilitários.

Visão geral

O CLI é o cliente atual da Juniper: um cliente fino que lê o que você digita, mostra a resposta chegando token a token e deixa a confirmação de ações acontecer na conversa. Toda a lógica continua em brain/core. Arquivo: brain/clients/cli.py (Typer + Rich). Por padrão o cérebro roda dentro do mesmo processo (deployment.mode: local); no modo server o CLI fala com o brain remoto (Modo server, Produção, Protocolo).

Tudo que o terminal diz segue o padrão de Voz no terminal.

Conversar

juniper "o que tenho amanhã?"     # uma mensagem: responde e sai
juniper                           # conversa (REPL)
python -m brain chat              # equivalente, sem instalar o atalho

Qualquer coisa que não seja um comando conhecido é uma mensagem: juniper oi e juniper "marca dentista amanhã às 16h" funcionam sem aspas ou comando. No REPL:

👤 VOCÊ: oi
🌿 JUNIPER: Oi! ...
👤 VOCÊ: /sair

/sair, /exit ou Ctrl+D encerram; Ctrl+C também (ainda não cancela só o turno).

Opções do chat

OpçãoO que faz
--provider, -p deepinfra/groq/ollamaForça um provider, sem failover (útil para testar o Ollama sem a Groq responder no lugar). Um nome inválido é recusado antes de qualquer trabalho, listando os válidos.
--resume, -rRetoma a conversa mais recente (Memória de sessão).
juniper -p ollama "oi"
juniper -r "e o prazo?"           # retoma e já manda uma mensagem

Códigos de saída

Uma mensagem única sai com 1 se nenhum LLM respondeu. No REPL, um erro de LLM é mostrado e a sessão continua. --provider inválido sai com 2; Ctrl+C sai com 130; memória indisponível sai com 1 (antes de falar com o LLM).

Modo server: o CLI falando com o brain remoto

Com deployment.mode: server, o juniper não monta o Agent no próprio processo: abre um WebSocket com o servidor (brain/clients/remote.py e remote_cli.py) e só entrega texto e mostra texto. A aparência é a mesma: juniper, juniper <mensagem> e --resume funcionam igual, com streaming, confirmação na conversa e o tempo por etapa quando o servidor liga agent.show_timing. Conversas, memórias e perfil ficam no servidor: existe uma memória só.

# config.yaml do cliente
deployment:
  mode: server
  server:
    host: 127.0.0.1          # o nome do servidor na rede (na VPS, o nome Tailscale)
    port: 8765
  auth:
    token_file: ~/.juniper/token   # o token que o servidor criou no primeiro boot

O endereço é ws:// (sem TLS): o token e a conversa só ficam protegidos dentro do Tailscale ou de uma rede privada. Se deployment.server.host for um endereço público, o CLI avisa antes de conectar.

No ambiente Docker de desenvolvimento (Produção), o token está em .juniper-dev/state/token; sem mexer no config.yaml: JUNIPER_DEPLOYMENT__MODE=server JUNIPER_DEPLOYMENT__AUTH__TOKEN_FILE=.juniper-dev/state/token juniper "oi".

  • Ctrl+C durante uma resposta cancela o turno (o chat continua); no prompt, sai.
  • Queda de conexão: o cliente reconecta sozinho (1, 2, 4, 8, 16 e depois 30 s, com variação; logo depois de um deploy, em até 2 s) e retoma a conversa. Se cair no meio de uma resposta, o turno termina no servidor e, ao reconectar, o CLI mostra a resposta que ficou salva. Sem servidor: "Juniper indisponível no momento".
  • Comandos de memória (list, search, forget, export, profile) falam com a memória do servidor; a confirmação do forget continua no cliente. memory reindex é administrativo e só roda no servidor.
  • juniper tools lista as tools do servidor (inclui as de executores conectados).
  • Comandos locais (search, deploy, install, docs, version) não precisam do servidor.
  • Cada processo do CLI é uma conexão própria (juniper memory list não derruba o chat aberto).

Como funciona

PeçaO que faz
chatComando do Typer: monta o router, o Dispatcher(conversational=True), a memória e o Agent, e chama converse.
converseUm turno (mensagem única) ou um laço de turnos (REPL). Entrega cada turno ao extrator de memória em segundo plano.
PrinterImprime cada token assim que chega, sem interpretar colchetes como markup do Rich (uma resposta com [bold] sai literal).
LineReaderLê o teclado numa thread, sem travar o event loop.
friendly_errorTraduz falhas do LLM em instruções em PT-BR.
ConfirmaçõesSem prompt: a Juniper pergunta em palavras e o seu "sim" é interpretado pelo sistema (Agente).

juniper memory

Precisam do MongoDB no ar; se não estiver, a mensagem diz o que fazer, sem stacktrace.

juniper memory list [--type preference|project|fact] [--all]
juniper memory search <termo...> [--limit N] [--threshold X]
juniper memory forget <id> [--yes]
juniper memory export [--vectors] [--output arquivo.json]
juniper memory profile                         # ver
juniper memory profile set "..." --name "..." --birth-date AAAA-MM-DD --nationality "..."
juniper memory profile forget [--yes]
juniper memory reindex [--force]
juniper memory beliefs [--all] [--min-confidence X]   # Memória V2
juniper memory beliefs show <id>
juniper memory beliefs forget <id> [--yes]
juniper memory affect [show <id>|clear]        # sentimentos; show rastreia a origem
juniper memory knowledge                       # o que ela anotou estudando
juniper memory knowledge show <tema>
juniper memory knowledge forget <tema> [--yes]
juniper memory journal [--days N]
juniper study add <arquivo|-> [--topic TEMA]    # ensinar a partir de um texto
juniper memory dream [--dry-run]
juniper memory prompt "<mensagem>" [--anterior "..."]   # o que a V2 acrescenta ao prompt

A personalidade viva tem os seus: juniper persona show (traços, versão, deriva), persona history e persona revert [--to N] [--yes] (volta a uma versão anterior como uma versão nova). Os comandos beliefs, concerns, affect, journal e dream são da Memória V2: leem o banco do processo onde rodam e, com a V2 desligada, dizem isso.

ComandoO que faz
listMais novas primeiro, com id, tipo, status, data e texto. --all inclui as superseded (só para auditoria).
searchMostra a nota de cada resultado: é a ferramenta para calibrar memory.retrieval.threshold (--threshold -1 mostra a nota de tudo).
forgetMostra o texto, pergunta "Pode apagar?" (padrão não) e apaga com as versões antigas. --yes pula a pergunta.
exportJSON com {"profile": ..., "memories": [...]}; sem os vetores, a menos que --vectors.
profileMostra, define (set) ou apaga (forget) o perfil.
reindexRefaz os vetores (Memória de longo prazo).

juniper docs

Serve a documentação localmente; abra http://localhost:47831 no navegador (a Juniper não abre sozinha). Ctrl+C encerra. Se a porta estiver ocupada, usa a próxima livre (47832, 47833...) e mostra o endereço certo.

Aliases escondidos

grep e gitgrep (= search) e deployfeature (= deploy) continuam funcionando, escondidos do --help.

Limitações conhecidas

  • Resposta em texto puro: não há renderização de Markdown (a persona fala em frases corridas, sem Markdown nem listas, e só usa blocos de código quando você pede código).
  • Ctrl+C encerra o programa mesmo no meio de uma resposta.
  • Se uma confirmação expirar, a pergunta antiga continua na tela até você digitar algo.
  • input() não pode ser cancelado: a thread de leitura é reaproveitada, e é daemon, então nunca impede o programa de fechar.

Testes

pytest tests/test_cli.py -v

Cobrem: versão, mensagem única com streaming, colchetes literais, REPL até /sair e até EOF, --provider inválido e válido, chave ausente (instrução do .env, saída 1), REPL sobrevivendo a erro de LLM, as dicas de friendly_error, o aviso de irreversível, o reaproveitamento da thread de leitura e um fluxo completo com confirmação negada. Para ver ao vivo, com a chave no .env: juniper "marca um teste amanhã às 10h".
