Contexto

O agente Juniper v3 executa ações no sistema operacional do usuário por decisão de um LLM. Isso introduz uma superfície de risco: o LLM pode interpretar mal a intenção do usuário, ou pode ser induzido (via prompt injection em conteúdo lido por web_fetch) a executar comandos destrutivos.

Precisamos de uma política clara, implementável e auditável que defina:

  1. O que o agente executa sozinho.
  2. O que exige confirmação explícita do usuário.
  3. O que é bloqueado independentemente de confirmação.

Decisão

Adotamos um modelo de 4 tiers de permissão. Cada tool declara seu tier como atributo de classe. O comportamento do agente é determinado pelo tier no momento da execução.

Tiers

TierDefiniçãoComportamentoExemplos
READNão modifica estado local nem envia dados para fora.Auto-executa. Loga em agent.jsonl.web_fetch (GET), web_search, gitgrep, ls, cat, git log, git status, rg, fd, jq (leitura)
WRITEModifica estado local ou envia dados para fora de forma reversível.Confirmação inline (prompt [y/N], timeout 60s).open_app, git commit, git checkout, edição de arquivo, curl POST, git push (sem force), npm install local, pip install em venv
DESTRUCTIVEModifica estado de forma irreversível ou envia dados sensíveis/conteúdo para fora.Confirmação inline com aviso explícito de irreversibilidade. Timeout 60s aborta com exit code 2.rm, rm -rf, esvaziar lixeira, git reset --hard, git push --force, git clean -fdx, mv que sobrescreve, > arquivo (truncamento), envio por e-mail/WhatsApp/Telegram, scp, rsync remoto, publish (npm/docker/pypi), docker system prune, git commit --amend em commit já pushado
FORBIDDENNunca executa, independente de confirmação.Bloqueio duro com mensagem de erro.dd em device, mkfs, rm -rf /, chmod -R /, chown -R /, escrita em /etc, /boot, /sys, /proc, /dev, kill -9 1, systemctl stop em serviços críticos

Regras de implementação

  1. Toda tool declara seu tier como atributo de classe (tier: Tier).
  2. Default = WRITE. Tool não classificada explicitamente é tratada como WRITE. Isso força revisão consciente ao adicionar tools novas em vez de auto-executar por esquecimento.
  3. Confirmação mostra o comando exato. Nunca um resumo, nunca uma paráfrase. O usuário precisa ver literalmente o que será executado.
