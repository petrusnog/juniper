T-020 — Base de Tools

O molde de toda ferramenta da Juniper: o que ela precisa declarar para o LLM conseguir escolhê-la, que nível de segurança ela tem e como devolve o resultado. Arquivo: brain/tools/base.py.

1. O que existe

Tool

Classe abstrata. Cada ferramenta herda dela, declara metadados como atributos de classe e implementa async run().

ToolResult

success, output, error, metadata. Retorno único de toda tool (ADR-002). Imutável.

Tier

READ · WRITE · DESTRUCTIVE · FORBIDDEN (ADR-006).

Locality

CLOUD · EXECUTOR: onde a tool roda (ADR-007). No Sprint 1 tudo roda local.

2. Como escrever uma tool

class OpenApp(Tool):
    name = "open_app"                       # snake_case, único
    description = "Abre um aplicativo ou URL ..."   # PT-BR: o que faz e quando usar
    parameters = {                          # JSON Schema
        "type": "object",
        "properties": {"target": {"type": "string", "description": "..."}},
        "required": ["target"],
    }
    tier = Tier.WRITE                       # opcional (default WRITE)
    locality = Locality.EXECUTOR            # opcional (default EXECUTOR)

    async def run(self, **kwargs) -> ToolResult:
        ...
        return ToolResult(success=True, output="abri firefox")

3. O que o LLM enxerga: to_schema()

O método de classe Tool.to_schema() converte os metadados para o formato OpenAI function calling do ADR-002, exatamente o que Groq e Ollama esperam no campo tools.

Classe Toolname · description · parameters
→
to_schema(){"type":"function","function":{…}}
→
LLMdecide se e como chamar

tier e locality ficam de fora do schema: são assunto do dispatcher (T-030), não do modelo. O schema devolvido é uma cópia; alterá-lo não muda a classe.

4. Validação na definição da classe

Quando o módulo da tool é importado, __init_subclass__ confere os metadados. Uma tool malformada falha na hora do import, não no meio de uma conversa.

namePrecisa ser snake_case (open_app, não OpenApp nem open-app).ValueError
descriptionTexto não vazio.ValueError
parametersObjeto JSON Schema: type: "object", properties dict, e required só com chaves existentes em properties.ValueError
tier / localityTêm que ser membros dos enums (uma string solta como "read" é rejeitada).ValueError

Classes abstratas intermediárias (sem run) não são validadas, então dá para criar uma base comum que só preenche parte dos metadados.

5. Decisões proativas

#DecisãoPor quê
1Validação em __init_subclass__ (a spec dava a opção de validar no registro).Falha mais cedo e independe do registry. A T-021 não precisa repetir a checagem.
2Erro de validação é ValueError com o nome da classe na mensagem.Simples e fácil de localizar o culpado.
3ToolResult é frozen (a spec dizia @dataclass simples).Segue os tipos de brain/llm/types.py; um resultado não deveria mudar depois de devolvido.
4Enums são StrEnum com valores em minúsculas ("read", "write"…).Serializam bem para logs JSON (T-031).
5Valida que required ⊆ properties (além do pedido).Um required apontando para parâmetro inexistente faria o LLM ser instruído a mandar algo que a tool ignoraria.
6Só to_schema() copia o parameters (deepcopy).O dicionário é compartilhado pela classe; sem cópia, quem mexer no schema alteraria a tool.
7Gancho opcional precheck() (adicionado com a T-022).Roda antes do [y/N]: a tool pode recusar uma entrada inválida ou em conflito sem incomodar o usuário nem gastar uma volta do LLM. O padrão devolve None (segue em frente).

6. Limitações conhecidas

Não valida os argumentos em tempo de execução. A checagem do JSON Schema contra o que o LLM enviou fica com o dispatcher (T-030).

A validação do schema é rasa. Confere a estrutura mínima (object, properties, required), não se cada propriedade é um JSON Schema válido.

Tier fixo por classe. A run_shell (T-023) terá tier dinâmico, decidido pelo comando; isso será resolvido nela e no dispatcher, e o tier da classe servirá como piso.

Ainda não há registro. Declarar a classe não a torna visível ao agente; isso é a T-021 (@register_tool).

7. Como testar

pytest tests/test_tools_base.py -v

Cobre: classe não instanciável, to_schema() igual ao formato do ADR-002 (e cópia independente), tier padrão WRITE e locality padrão EXECUTOR, run() devolvendo ToolResult, enums, classe intermediária abstrata e cada regra de validação (nomes inválidos, descrição vazia, parameters malformado, required inconsistente, tier/locality inválidos).
