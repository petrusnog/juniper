Arquitetura guia

As camadas da Juniper, as regras que as mantêm simples e o caminho de uma mensagem.

Visão geral

A Juniper segue a lógica de um assistente sempre disponível: um cérebro (o agente, que pensa) e vários corpos (interfaces e executores: o terminal, o desktop, o celular). Os clientes são finos: capturam a sua mensagem e mostram a resposta. Quem decide é o cérebro.

Analogia: a interface é o balcão de um restaurante, o cérebro é o chef, as tools são os equipamentos da cozinha e a memória é o caderno de receitas e pedidos antigos. O balcão nunca cozinha e o chef nunca atende na rua.

Hoje o cérebro roda dentro do processo do CLI (deployment.mode: local). A Sprint 3 o leva para uma VPS e conecta clientes remotos (veja Produção).

Uma frase sua, passo a passo

Exemplo: você digita "amanhã quero uma ida ao dentista, às 16h".

#O que aconteceCamada
1A CLI recebe a frase e a entrega ao Agent.Interface
2O agente monta o pedido ao LLM: persona, perfil, memórias relevantes, a hora de agora (é isso que permite entender "amanhã") e a lista de tools.Cérebro
3O LLMRouter envia à DeepInfra; se ela falhar, tenta a Groq e, por último, o Ollama, com a mesma conversa.Capacidades
4O LLM pede create_event com título e horário já resolvidos.Capacidades
5O Dispatcher acha a tool no registry; o precheck consulta o Google Calendar antes de te perguntar qualquer coisa.Cérebro
6Se já houver algo às 16h, a Juniper pergunta: "Já existe «Fisioterapia» às 16h. Desmarco para marcar o dentista?"Cérebro
7Sem conflito, ela pergunta em palavras "Posso marcar «Dentista», segunda 16h–17h?" e espera o seu "sim" (confirmação na conversa).Cérebro
8Você confirma; o evento é criado e aparece no seu celular. A resposta chega palavra por palavra.Capacidades → Interface
9Tudo é registrado no log, a conversa é salva e, em segundo plano, o que vale lembrar vai para a memória.Transversal

Regras que mantêm tudo simples

  1. O cérebro não conhece as interfaces. brain/core/ nunca importa de brain/clients/. Por isso a mesma Juniper serve terminal, desktop e voz.
  2. Providers são trocáveis. O cérebro fala com "um LLM" (LLMProvider), nunca com DeepInfra, Groq ou Ollama especificamente. O router escolhe.
  3. Tool nova = arquivo novo. Cada capacidade é um plugin que se registra sozinho (Tools). Nada no cérebro muda.
  4. Perigo exige permissão. Ler é livre; alterar pede o seu "sim" na conversa; destruir também, com aviso de irreversibilidade; o que é proibido nunca executa (Segurança).
  5. Um só ponto de configuração. Nenhum módulo lê variável de ambiente ou YAML diretamente: tudo vem de brain.config.settings (Configuração).
  6. Shell é interface, Python é cérebro. O shell/ só orquestra e chama; a lógica vive em brain/.
